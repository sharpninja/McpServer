### F-R23-01: arrival sequence does not distinguish redelivery from a separate identical event

**Plan locations:** D1 and its every-delivery promise, line 29; common nonce rule, lines 78-79; Copilot and classic-Cline rows, lines 86 and 89; FR-MCP-SESSIONTURN-001-AC003, line 195; pure PowerShell nonce interface, line 343; pure Node nonce interface, line 350; A3 RED, line 579; A9 host adoption, line 591. TODO implementationTasks 13, 18, and 19 inherit the host contracts.

**Exact defect:** Round 23 adds `arrivalSeq` for each hook invocation, making two distinct arrivals with equal session, timestamp, and prompt different. The same fields are also all that identify a repeated delivery of one arrival to a new hook process. The plan promises that repeated deliveries of that event reuse one nonce, and A3 expressly tests two independent processes fed the same recorded Copilot payload opening one turn. Under the new rule, those processes allocate different sequence values and mint two turns. Conversely, reusing a sequence by matching the equal payload would collapse the separate messages that round 23 sought to distinguish. D11's one registered hook does not establish a stable event key or prohibit one registered hook from being invoked again. The pure `(host,payload)` nonce signatures also cannot both incorporate a mutable sequence and satisfy their stated equal-payload-equal-nonce contract.

**Evidence and what-if:** For session S, timestamp T, prompt P, two distinct arrivals produce `H(S,T,P,1)` and `H(S,T,P,2)`, as intended. A redelivery of one arrival to two hook processes with the same observed S/T/P also produces `H(S,T,P,1)` and `H(S,T,P,2)` if each invocation increments the counter. The persisted failsafe record supports *drain of that particular record*, but the plan gives a second hook process no traceable key to find that record instead of allocating a new one. This conflicts with lines 29, 195, 343, and A3's two-process RED. The local Cline source `/home/sharpninja/github/cline/apps/vscode/src/core/hooks/hook-factory.ts:224` sets `timestamp` with `Date.now().toString()`; `apps/vscode/proto/cline/hooks.proto:56-60` gives UserPromptSubmit prompt and attachments, with no per-message id. The same issue applies to Copilot under the plan's listed fields. The r14 and r22 findings show recurrence in event identity, not a mere missing hash input.

**Change to PASS:** In P0.2 determine whether each host exposes a stable event identity shared by every delivery/retry of one message and distinct for separate equal-field messages, or an earlier queue event that can carry a durable plugin-generated identity. Lock the source, nonce interface, replay lookup and negative probe in the host rows, FR-001-AC003, TR-001/TR-008, TEST-001/TEST-008/TEST-009, A3/A8/A9 RED, and the TODO description/technicalDetails. If neither traceable mechanism exists, apply already-locked D6 `turn_logging_unsupported` for that host and test zero mint/write; do not promise both invariants. **Implementer plan/TODO edit; no operator decision** under D1, D6, and D11. Weakening one-turn-per-event would instead need an explicit operator decision, which this review does not request.

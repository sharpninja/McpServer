    title: Do not exit 1 when updateTurn queues a session_submit failsafe

    description:
    - workflow.sessionlog.updateTurn writes current-turn.yaml first, then Invoke-ReplPersistTurn writes a unique session_submit failsafe and calls client.SessionLog.SubmitAsync. On timeout/HTTP 503/backend_unavailable, persist returns false with degraded/queued details and keeps the failsafe, but does not emit that contract. Invoke-WorkflowUpdateTurn treats the false as failure, repl-invoke.ps1 exits 1, and Invoke-McpPlugin.ps1 throws Plugin command failed with exit code 1. That unclassified throw is indistinguishable from a rejected update, so a retry writes another timestamped failsafe and risks duplicate SubmitAsync replay. This violates FR-MCP-171, which requires the same retryable degraded/queued envelope as the existing command_timeout path and forbids throwing.

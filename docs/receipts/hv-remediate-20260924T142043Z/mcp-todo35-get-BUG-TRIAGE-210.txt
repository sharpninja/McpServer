    - workflow.sessionlog.appendActions persists through Invoke-ReplPersistTurn as a full-session POST to /mcpserver/sessionlog (client.SessionLog.SubmitAsync). TransactionGatedSessionLogService wraps that write as operation sessionlog.submit. When the turn-transaction subscriber rejects the post-mutation commit, the coordinator rolls back the session graph and SubmitAsync throws InvalidOperationException. SessionLogController.ClassifiedError maps that to HTTP 500. The plugin writes a failsafe payload before the call and does not treat HTTP 500 as the retryable 503/timeout queue path, so the exception is thrown and the failsafe file is retained. For an existing session, rollback restores the pre-mutation graph, so the appended actions never stay on server truth and the active turn is not current until that failsafe can replay. Local turn-cache audit counters are incremented before persist, so cache and server diverge after rollback.

    - workflow.sessionlog.updateTurn is handled locally in plugins/core/lib-ps/repl-invoke.ps1 and then persisted through Invoke-ReplPersistTurn -> Invoke-ReplTurnUpsertParams -> New-McpPluginTurnUpsertRequest. QueryText is [Parameter(Mandatory)][string] with no AllowEmptyString, unlike Title which was already fixed for the same ParameterBindingValidationException (TR-MCP-REPL-018). updateTurn omits Title unless queryTitle is explicit, and QueryText is recovered only from current-turn.yaml then that empty Title. A valid model update (response, tags, contextList) therefore throws, the wrapper returns false (exit 1), and the live MCP turn is not patched. Persist-log tests never exercise this path; the STRICTCOUNT fixture even omits queryText and short-circuits before upsert. A session_submit failsafe can remain from write-ahead persist or an earlier beginTurn, but it is not a successful live-turn update.

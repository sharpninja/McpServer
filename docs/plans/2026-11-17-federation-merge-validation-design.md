## Candidate retention, transfer and GC experiment

Trace: TASK-FEDPH0-006/B6 and TASK-FEDPH0-007/B12; FR-MCP-180/TR-MCP-FEDERATION-007/TEST-MCP-228, particularly ac-SameCellConflictNeedsReview and ac-DeleteUpdateNeedsReview. B6/B12 additionally require engine evidence beyond those two criteria. The current live Layer 1 definitions were reread on 2026-11-17; no definition, criterion or acceptance state changes here.

The pinned-source receipt is `docs/receipts/federation/20261117-phase0-dolt-retention-source.json`. It records decoded LF UTF-8 source hashes and exact line excerpts from Dolt2.7.4 commit9e4102e303610fc4681de16a9f7bbbc870d884a3. Source observations:

- `ref/ref.go` accepts ordinary branches under `refs/heads/`; `review/<ReviewId>/...` is a branch path, not an invented `refs/review/` ref type. A branch name alone supplies no access control. Private review/integration repositories and gateway/branch permissions must establish isolation.
- `env/actions/remotes.go` resolves a source branch to a commit, copies reachable chunks, then advances the destination ref. It does not transfer the source working set through that branch-push path. `doltdb.GC` starts from persisted dataset roots after pruning unreferenced datasets. An external control-store hash is not one of those roots.
- `env/actions/commit.go` rejects data conflicts, constraint violations and schema conflicts when force is absent. The SQL allow-conflicts setting is not the same check as this Dolt-commit gate. `dprocedures/dolt_commit.go` sets the session force-transaction flag when the force argument is used.
- `doltdb/workingset.go` stores schema-conflict table names in MergeState and reconstructs alternatives from the pre-merge root and incoming commit. `dsess/transactions.go` clears merge state during Dolt-commit preparation. Therefore a forced candidate commit is not assumed to preserve every kind of review evidence. This is a concrete risk to measure, not a declared engine failure.

Use fresh H/A/B fixture repositories for each case and configuration. Record base C0, valid local B1, valid incoming A1, protected Atlas/feature F1 and Other/main X0. Pin C0/B1/A1 using supported ordinary private branch paths `review/<ReviewId>/base`, `/local` and `/incoming`. Candidate and source refs must resolve locally and remotely until a durable authorized-resolution receipt permits release. The same-cell and delete/update fixtures use the exact earlier values. Additional B6 cases separately create unique, FK, check and not-null violations, a schema conflict, a clean domain cycle and unrelated histories. Do not fabricate a common ancestor. Not-null/check behavior may be immediate rejection rather than a stored violation; capture the actual outcome and assess whether the approved review behavior can be met.

Run a fresh unpooled private connection for each persistence configuration: default SQL COMMIT; allow-conflicts SQL COMMIT; ordinary DOLT_COMMIT after default merge; ordinary DOLT_COMMIT with allow-conflicts; and, as an explicitly experimental comparison, private forced DOLT_COMMIT with and without allow-conflicts. Keep automatic Dolt commits disabled. Include explicit-transaction and autocommit cases and --no-commit merge observation where supported. Every connection's before/after settings, branch identity, result rows and errors are captured. Global values and every live/public connection remain zero for automatic commit, allow-conflicts and force-transaction overrides. Close the experimental connection; reopen with fresh defaults and verify isolation. No configuration becomes the selected persistence design merely by creating a hash.

At each successful private persistence attempt, read actual conflict cells with base/local/incoming values and deletion markers, constraint records, schema alternatives and validation errors. Independently capture full candidate rows/schema, source and candidate hashes, local and remote ref maps, live working-set hashes and history. A missing remote pin, a clean-looking result obtained by discarding alternatives, or a live/public head change also fails. Capture default-ref discovery and explicit-fetch behavior so retention does not accidentally rely on a live SQL session or an untransferred dirty working set.

If a review candidate cannot be represented as a transferable commit without losing an artifact, record the failed round trip. This remains an unselected candidate approach and must still meet both local/remote ref retention and full review recovery. A backup file or JSON-only review does not replace the required physical refs. No custom merge algorithm, live override or weakened retention rule is permitted.

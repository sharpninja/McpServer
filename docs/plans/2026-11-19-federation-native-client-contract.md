## Opt-in policy and precedence

The proposed patched CLI loads a nonsecret JSON file only when its child-process environment contains DOLT_FEDERATION_TRANSPORT_POLICY. The value is an absolute file path. The disposable Nuke integration harness creates it under its run-specific root and sets the variable only on that Dolt child. It never modifies operator-global Dolt settings or machine environment. Absent variable preserves stock upstream mode. Present-but-empty, missing file, unreadable, malformed, duplicate/unknown properties, unsupported schema or invalid values fail locally with federation_transport_policy_invalid and exit1, without helper launch, socket or fallback to stock mode.

The version1 object has exactly these fields: schemaVersion (integer1); gatewayOrigin (HTTPS origin); caBundlePath (absolute PEM file path); spkiSha256Pins (nonempty array of unique Base64 encodings of32-byte SHA256 SPKI digests); helperExecutable (absolute pwsh executable path); helperArguments (ordered JSON string array). No token, password, signing key or other secret belongs in this file. The configured origin has no userinfo, query, fragment or non-root path. Canonical comparison uses parsed HTTPS scheme, canonical DNS/IP host and effective port; explicit443 and omitted443 are equivalent. CA bundles contain public certificates only. Do not trust a TLS policy solely because its JSON parsed.

Strict mode owns the helper selection and TLS configuration for that invocation. Reject incompatible insecure, alternate-password or alternate-helper overrides before any connection rather than silently selecting one. Do not write a new globally persistent Dolt setting. Preserve the executable-only upstream helper form when strict mode is absent. The selected strict route disables environment HTTP proxy routing, so node credentials travel directly over the approved lab route to the exact gateway origin; backend credentials remain gateway-only.

## Helper process and private protocol

Launch the configured absolute pwsh executable directly through exec.CommandContext with an argument vector, never a shell. In the Ph0 policy helperArguments is exactly [-NoProfile, -NonInteractive, -File, <absolute helper.ps1 path>]. Append the upstream get operation as one final argument. The script path can contain spaces or shell metacharacters and remains one literal argument. Resolve both executable and script under the verified host inventory before launching. No token appears in argv, inherited secret environment or a generated file. The invocation-local token broker is the previously specified protected current-user pipe; its process-scoped reference is nonsecret. Named-pipe ownership and permissions must be proved on each host before tokens are used.

Write exactly one UTF8 upstream request object containing uri=gatewayOrigin on stdin. The helper accepts get only, rejects another origin, and emits exactly one upstream JSON response on private stdout: headers maps Proxy-Authorization to one bearer reference-token value; expires is optional RFC3339 UTC time. If supplied it must be strictly in the future. No additional protocol is invented. Existing normalization rejects reserved headers, invalid values, duplicate/conflicting metadata and trailing JSON; strict mode additionally requires exactly the one intended proxy credential value. The helper's response remains process memory and is never emitted to receipts or public stdout.

Helper-cache behavior remains upstream refresh-skew semantics. Gateway introspection is independent and uncached on every new request. Revocation therefore rejects the old token even when the helper reused it. A successful helper invocation alone is not proof of token issuance, project authorization or revocation.

## Safe local outcomes

Use these non-HTTP local codes with CLI exit1: federation_transport_policy_invalid for policy/override rejection; credential_origin_refused for an invalid advertised destination before connection; credential_helper_failed for start, nonzero exit or unavailable broker; credential_helper_response_invalid for malformed/trailing JSON, expired or rejected header data. Public client stdout is empty on these failures and stderr contains only the selected code plus a newline. Cancellation propagates through the existing command context and must terminate the helper; cancellation is not retried as successful credentials. No raw helper stderr, stdout, decoding value, executable exception detail, URI, token or error cause is interpolated into public diagnostics. These internal client codes do not change gateway HTTP codes.

On success the normalized observation is exit0, empty public diagnostics, one direct helper launch, unchanged ordered arguments, one origin-only stdin request and Reference credentials on the Proxy-Authorization channel. The real observer compares credential bytes against the invocation-private canary before returning that classification. It must never return the canary or raw helper response. On helper failure zero bearer requests are permitted. Capture and scan public stdout, stderr, exception text and helper diagnostics; require every capture to be present and scan extra returned channels too. The broader Task007 thirteen-channel credential scan remains required.

## Shared TLS and exact-origin enforcement

Build one immutable strict policy per invocation. Both protected unary/stream gRPC and object HTTP use the same configured CA trust, expected gateway host and allowed SPKI pins. Verify the ordinary chain, validity period and SAN/hostname, then require a matching SHA256 SPKI pin before transmitting any bearer value. No InsecureSkipVerify or trust-on-first-use. The HTTP client redirect callback enforces the same origin before following. Every advertised object location is validated before the first network operation. Reject foreign host/subdomain, different effective port, HTTP downgrade, userinfo and fragment. Resolve relative redirects against their current request before comparison; preserve permitted sealed path/query bytes rather than decode/re-encode signed locations.

TLS observation scenarios cover grpc-unary, grpc-stream and object-http. A valid peer yields ordered policy_loaded, tls_verified, bearer_sent with one bearer send. Untrusted CA, wrong SAN, expired certificate or unapproved SPKI yields policy_loaded, tls_rejected, tls_peer_untrusted and zero bearer sends. The test observation identifies the actually installed trust policy and peer using safe fixture labels only after in-memory certificate/pin comparison, not by echoing configuration. Both hosts must later run those same assertions against real certificate handshakes. Existing control-endpoint TLS assertions remain required in Task007.

## Exact repository-selector binding (2026-11-19)

The retained proto and remotesrv/grpc.go at9e4102e303610fc4681de16a9f7bbbc870d884a3 are authoritative. RepoId consists of org and repo_name. getRepoPath prefers nonempty repo_path, otherwise org/repo_name. CommitRequest has repo_id(field1) and repo_path(field5), with no repo_token. The other11 RPC requests have repo_id, repo_path and repo_token; GetDownloadLocations and StreamDownloadLocations share GetDownloadLocsRequest, while StreamChunkLocations uses its own request. Do not invent a token field on Commit or rely on the backend's selector precedence for authorization.

The disposable gateway has an explicit allowlist from exact wire repository identity to project, physical repository and role Public or Upload. Every nonempty RepoId, repo_path and opaque repo_token must resolve to the same physical repository and role, not merely the same project. Unknown, malformed, absent-all or conflicting selectors return403 unauthorized_project before backend lookup/transfer. An opaque repo_token remains a repository selector, never an authorization token; a valid selector cannot grant project rights. Values are not interpreted as filesystem paths, URL-decoded twice or accepted by prefix. Fixture upload repositories bind node and publication request; the public and upload repositories of Atlas are distinct entries. The gateway checks this mapping on every streamed message, even when the backend would switch stores midstream.

Read methods can address an allowed public repository after read authorization. GetUploadLocations, AddTableFiles and Commit require publish authorization and an allowed private upload target. A read-only token receives403 unauthorized_project for mutation. A publish token addressing a public target receives409 publication_required without forwarding; only the fenced publication.accept path can advance public state. Rebase must not be treated as publication authorization merely because the pinned implementation returns an empty response. Backend-issued selectors are accepted only through the same exact allowlist/binding, never by trusting a token's presence. No selector is logged as a bearer credential.

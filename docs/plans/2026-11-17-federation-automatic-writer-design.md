## Proposed routing and observable consequences

- Requirements reads call conditional initialization. Missing workspace/default-layer rows can be created; requirements/mappings are imported only when the requirement store is empty and documents exist. Existing data short-circuits import. This does not establish that a read changes an existing requirement or its timestamps. Preserve standalone behavior. An enrolled-project read never imports authored content or creates scope definitions; explicit initialization/import enters the owning branch's write gate. Host registry and active-layer selector remain protected operational state.
- McpDbContext SaveChanges overloads invoke shared preparation. Its order includes workspace stamping/canonicalization, shadow soft deletion and relationship cascades, physical-delete/audit-update guards, implicit workspace rows, audit snapshots, then string sanitization. Project deletion semantics remain inside the owning write gate; host rows and append-only audit remain outside cloneable content. Migration manifests compare actual saved typed values, including conventions, rather than assuming inputs were stored unchanged. Import preserves original audit provenance and does not recreate original events as newly authored changes.
- Startup session PlanFile/TodoId backfill targets operational turns missing those values and saves only on change. Its wrapper logs failures without rethrowing. Keep this routine away from explicitly promoted immutable session snapshots and from versioned-project startup.
- Memory Index/Reconcile/BatchIndex dispatch constructs contexts directly and writes derived indexes plus EmbeddingStatus, including failure/pending status. Route derived/status writes to a branch-scoped operational projection; do not attach a versioned MemoryEntity simply to persist status. Preserve authored Workspace content and version graph. Global/machine memories remain operational.
- Explicit memory links and learned co-retrieval share MemoryEdgeEntity. Version explicit portable links only when both endpoints belong to the same project. Keep co-retrieved edges/weights operational; retain their data. Disabled Hebbian behavior remains a no-op. A whole-table routing or deletion rule would be incorrect.
- Workspace registry/config projection seeds missing local rows conditionally. Host paths, enablement and active-layer selector remain local/protected. Only the separately approved portable prompt/settings projection can enter authored history.
- MCP sync_run explicitly invokes ingestion after its existing transaction defer check. It upserts raw documents/chunks, embeddings/vectors and operational session tables. This callable path does not prove an unattended scheduler. Preserve these raw/derived records operationally; only explicit sanitized document/session promotion enters history. Existing ContextDocument/Chunk classifications remain LocalOperational.
- Non-Test storage-ready startup seeds absent built-in agents and publishes notifications after save. IgnoreQueryFilters checks existing IDs, including soft-deleted rows. Keep runtime definitions and notifications operational; migration/import must not replay startup seeding as an external effect.

`mixed-writer-boundaries.json` adds seven source-reviewed flows, 21 exact excerpts from 12 files and 35 covered catalog candidates. Counts overlap earlier receipts and must not be summed as unique coverage. The proposed boundary follows the whole logical operation:

- Requirement recovery currently saves authored rows and the replay hash/result in one serializable transaction. Splitting them must preserve exact payload/result binding and item-graph integrity across crash/retry. Architecture sections 3 and 11 explicitly disclaim cross-store atomicity and require recovery; a current transaction wrapper does not prove the future behavior.
- TODO creation/update/deletion includes children, requirement links and local audit before SaveChanges. Link helpers can also revive/create requirements. Fresh DI scopes resolve McpDbContext and copy host workspace identity today. The project/branch identity must instead remain bound through the owning command, its helpers and compensation. Audit and file-projection status stay operational; authored children, valid links and portable metadata stay with the project. A post-save YAML projection failure does not roll back the saved draft and must not cause duplicate audit or content on retry. Preserve retired-requirement policy rather than reviving a row just because a link references it.
- Memory Add/Update saves authored state, then a version, then attempts session activity; Revert saves content and its new version together. Version parents follow their memory's scope. EmbeddingStatus and automatic session actions remain operational. Scope-change requests are an explicit cross-store design and validation case; a same-ID lookup or whole-table route cannot prove safe movement.
- Workspace creation can invoke explicit dump import after saving host registry data. Existing Wiki import writes a TODO/link projection and may copy a YAML archive; this is not the all-domain, all-branch migration/export contract. Enrolled-project import uses its approved explicit migration/application gate while standalone behavior remains intact. Keep original archives.
- Transaction compensation directly restores memory, session and tool state, sometimes through its own current DB transaction. It must retain the original project/branch identity and owning gate, preserving exact applicable graphs, tombstones and protected operational state. A helper named Exact is not evidence that every newly split field is covered.
- Legacy memory/requirements/session adapters directly save or dispatch old replay operations. Standalone/non-enrolled behavior is retained. An enrolled versioned project cannot run both this replay and Dolt publication/integration; incoming history is not executed as business commands. Existing queue/conflict records require retained, explicit cutover disposition.
- The token-store UpdatedAtUtc candidate writes an encrypted JSON file, not an EF row. It stays protected host-local. This is a concrete counterexample to equating every automatic assignment with a database writer.

Required real-binding observations include crash/reopen at each save boundary, exact original and resulting authored graphs, independent operational/audit/replay records, unchanged unrelated project/branch and promoted snapshots, original-context compensation, and no duplicate version/audit/external effect.

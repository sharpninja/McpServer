## Test-owned interface and independent observations

`IPhase0Task006SupplementProbe` is a test adapter interface, not a new service endpoint. `Prepare(Phase0Task006Command)` receives scenario, project Atlas, branch main and request UUID `733477c8-974b-4877-9356-3a8b2ddcb948`. `Execute` performs the fixed fixture sequence. `ReadFrames` returns exactly before, held and after snapshots. `ReopenAndRead` closes owning processes and reopens retained stores before independently querying the final state.

A frame contains boundary, exact `Phase0Task006Fact(Path, Type, Value)` inventory and a logical receipt address `task006/<scenario>/<boundary>`. Receipt addresses must resolve through the retained native-run manifest to command, response and independent query files plus SHA256. A nonblank unrelated receipt is rejected. Fact paths are unique and exact; types distinguish null from empty and retain numeric precision. Missing, duplicate, extra, foreign, differently typed or changed values fail. Enumeration order is irrelevant; before/held/after order is required. The mock scripts use separate literal data and never call the assertion oracle's expected-value function.

The independent native observer must query stores through a second connection or a restarted process, never echo the operation response, the test's expectation dictionary or in-process mutation counters. Raw commands, exit status, stdout, stderr, all SQL result sets, selected session variables, commit graphs, branch refs, typed rows and filesystem hashes are retained. Every observation carries project/branch/request identity and its boundary. Native faults are injected by the disposable runner/process supervisor; no production fault-injection API is proposed.

`C0`, `A1`, `B1`, `F1`, `J1`, `M1`, `S1`, `U1` and named hash strings in mocks are fixture symbols. A native receipt binds each immutable source symbol to the actual SHA/typed fixture bytes before the operation under assertion. Generated result symbols bind to the first independently observed successful commit at the specified boundary, before crash/retry, with exact parent/trailer/content checks. The binding is injective, immutable and retained; later reads compare actual hashes against that binding. Missing/ambiguous bindings fail. A normalizer may not relabel a changed result as the expected symbol or derive expected contents from returned data. Native command spellings and schemas must be confirmed against the approved pinned Dolt source and the B2 catalog before implementation; this design is not evidence that any native command already works.

## B9 admitted edits, owner crash and commit idempotency

The owning server is the only live writer. OS file handle/mutex ownership is separate from the persisted lease/fence. Admission validates project, branch, owner session, fence and working-set preview; it holds the same project gate through the SQL transaction or commit. Expiry rejects new work and never aborts an already-admitted edit. Existing `Phase0SafetyBoundaryContract` exercises takeover during admission. A changed fence returns existing `lease_lost`; a changed preview returns `working_set_changed`; dirty takeover returns `branch_busy`. The unchanged draft and all unrelated refs remain visible.

Worker fast-forward, merge, resolve, schema and recovery operations request the owning server's gate. At held boundary, an admitted owner edit holds it, the worker is waiting and has made zero live SQL writes/mutations. The edit changes W1 to dirty W2. After release, worker re-reads W2 under the same gate and returns `waiting_local_work`, without resetting/capturing the draft. Task005 owns the separate worker SQL/remote/ref privilege discrimination; this document reuses the same owner API path and introduces no extra coordination mechanism.

Start a second owner while the first still holds its OS lock, then stop the first process and restart. The second is denied until confirmed first-process exit/lock release, then becomes the sole owner. Reopen retains the unpublished commit and dirty draft; no force reset or overlapping writer is accepted. Capture actual process identity/lock acquisition results, not only lease rows.

Use fixed request UUID R1 with branch main, parent C0 and payload hash payload-1 in commit trailers. Three independent crash windows are required: before Dolt history commit (no A1, no receipt), after durable A1 but before receipt/intent (A1 plus exact trailers, no receipt), and after receipt/intent but before reply (A1 and one durable receipt/intent, acknowledgement absent). Restart scans actual local history and matches request, branch, parent and payload before deciding whether to create or return a commit. All retries return the identical A1; there is exactly one history commit, receipt and publication intent. Reusing R1 with different payload is `request_id_conflict` with original receipt/draft retained. No exactly-once transport claim is made.

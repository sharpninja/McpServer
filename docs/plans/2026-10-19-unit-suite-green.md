### 21.9 What-if pass (for this section)

- A configured timeout of exactly 4294967 s: used; `CancelAfter` accepts it (bound by the runtime check). 4294968 s and larger: the default, never an exception.
- A value with blanks or a leading plus sign: parsed as before (`NumberStyles.Integer`), since the earlier parser accepted the same forms; a decimal or a thousands separator: the default.
- A culture whose digits or signs differ (tr-TR): the parse uses the invariant culture; the time-zone and culture gate run is the proof.
- The variable changing while a command runs: the timeout is read once per command, so the message names the timeout that applied.
- The stream timeout: the same rule. Until 21.6 no unit test reached the stream path's `CancelAfter` with an out-of-range value; `ProductionStreamCommand_SatisfiesTheContract` now does (2147483647, 4294968, 4294967), and the max runs cover both names under the real environment.
- The variable read more than once per request (the message could then name a different value than the timer used): the call-site contract fails any call site that reads its variable other than exactly once per run.
- A call site reading the other call site's variable: the contract fails it in every row.
- A command that finishes in the same instant the timer fires: either outcome is valid; the contract uses only commands that answer at once or never, so no row depends on that race.
- A new call site that reads a REPL timeout variable: the search finds exactly two readers, both through `ReplCommandTimeout.Read`; a third would need its own binding to the contract.
- A future numeric variable read by production: the max, zero and min runs set every numeric variable in the gate's list; a new name joins the list through the one-time search, which stays a search, not a scanner.
- A junction alias that already exists: the fixture creates a fresh alias path per fixture; `CreateDirectory` on an existing empty folder would turn that folder into the junction, and a non-empty one fails the reparse call (`Win32Exception`), never silently.
- A target path with a space or longer than the sample: the field-by-field decode row covers a space; the lengths are checked against ushort (`checked`), so an oversized path throws instead of writing a wrong buffer.
- The fixture on Linux: unchanged, `Directory.CreateSymbolicLink`; the Windows binding is Platform=Windows and runs only in the Windows lane, and it throws, never returns, if it ever ran elsewhere.

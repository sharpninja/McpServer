# QBAgent User Guide

QBAgent is a coding agent that uses [QuadBrain](QUADBRAIN.md) as its model. It starts in a folder, reads
the workspace marker there, connects to the McpServer QuadBrain service as an OpenAI-compatible model, and
runs the Microsoft Agent Framework tool loop: QuadBrain decides, QBAgent executes the tool calls.

QBAgent talks to QuadBrain and nothing else - there is no other endpoint and no fallback.

## 1. Running QBAgent

QBAgent runs in a working directory (the agent's "start directory"):

```bash
# uses the current directory as the start directory
dotnet run --project src/McpServer.QBAgent

# or pass an explicit start directory
dotnet run --project src/McpServer.QBAgent -- F:\path\to\workspace
```

On start, QBAgent looks for an `AGENTS-README-FIRST.yaml` marker in the start directory:

- **Marker present and valid** -> QBAgent binds to QuadBrain and starts the interactive loop.
- **No marker** -> QBAgent prints an informational message and exits cleanly (exit code `0`), contacting
  no endpoint.
- **Invalid marker** (missing `apiKey`/`baseUrl`, or a non-absolute `baseUrl`) -> QBAgent reports the
  problem and exits with code `2`.

## 2. The marker file

The marker (`AGENTS-README-FIRST.yaml`) is generated by McpServer when it starts and lives in the workspace
root. QBAgent reads only these top-level fields:

- `baseUrl` - the McpServer base URL; QuadBrain is reached at `{baseUrl}/v1`.
- `apiKey` - the per-workspace token, used as the Bearer credential to QuadBrain.
- `workspacePath` - the workspace root (used to locate skills and to scope server-side tool mutations).

If you receive `401` errors, re-read the marker: the token rotates each time the server restarts.

## 3. The tool surface

QBAgent exposes a fixed set of action tools to QuadBrain. They follow a "both-planes, one-core" design:
the agent-side tools are thin transport adapters, and the real safety logic lives once on the server.

### File tools

`read_file`, `write_file`, `list_files`, and `edit_file` route every operation through the MCP client to
the server's `RepoFileService`. The server is the single enforcement gate for:

- **Path safety** - traversal outside the workspace is rejected.
- **Allowlist** - writes are confined to the configured `Mcp:RepoAllowlist` globs.
- **Audit and transactional rollback** - every write/edit is audited and transaction-gated.

`edit_file` applies a targeted find-and-replace (`path`, `oldString`, `newString`, optional `replaceAll`
and `expectedOccurrences`). An ambiguous match (multiple occurrences without `replaceAll`) is rejected.

### Shell tools

- `run_powershell` - runs PowerShell in a single hosted session reused across the agent run, so the working
  directory and variables persist between calls. Invocations are serialized.
- `run_bash` - runs a command through Git Bash when available. If `bash.exe` is not on `PATH`, the tool
  reports unavailability gracefully (it does not fail the turn); fall back to `run_powershell`.

### Git tool

`git` runs allowlisted subcommands (`status`, `diff`, `log`, `branch`, `add`, `commit`, `checkout`, `push`,
`reset`, `show`, `fetch`, `rev-parse`, `remote`) with no shell, so arguments cannot be shell-injected.
`git push` is **disabled by default**. When push is enabled it is **origin-only**: URL remotes
(`https://...`) and SCP-style remotes (`git@host:repo`) are rejected, and a missing remote is forced to
`origin` so a push never relies on ambient defaults.

## 4. Skills

QBAgent supports [agentskills.io](https://agentskills.io)-style skills for progressive disclosure: the
agent sees a short list of available skills up front and loads a skill's full instructions only when it
decides to use it.

- Skills live under `{workspacePath}/skills`. Each skill is a folder containing a `SKILL.md` with YAML
  frontmatter (`name`, `description`) followed by the full instructions body. Nested and flat layouts are
  both discovered.
- At startup QBAgent injects a discovery preamble listing each skill's `name` and `description`.
- Two skill tools are exposed to QuadBrain:
  - `list_skills` - enumerate available skills (name + description).
  - `load_skill` - load a named skill's full instruction body before acting.

To add a skill, create `skills/<my-skill>/SKILL.md`:

```markdown
---
name: my-skill
description: One-line summary used in the discovery list.
---

Full instructions the agent loads when it calls load_skill with "my-skill".
```

## 5. How a turn runs

1. You enter a coding prompt at the interactive loop.
2. QBAgent sends the prompt to QuadBrain at `{baseUrl}/v1` (QuadBrain is the model). QBAgent attaches its
   session so concurrent agents stay isolated.
3. QuadBrain returns either a final answer or tool calls. QBAgent executes external tool calls (file,
   shell, git, skill) and feeds results back; MCP-internal tools (TODO, repo, requirements) are executed
   server-side by QuadBrain itself.
4. The loop continues until the task is done. Enter `exit`, `quit`, or `:q` (or send EOF) to stop. A tool
   failure is reported without aborting the loop.

## 6. Execution profile

QBAgent runs under the **standard (non-ACID) profile** so its action tools are available. (An earlier
design coupled the coding agent to the ACID transaction profile; that is intentionally not applied to
QBAgent. The server-side safety gates - path allowlist, transactional file writes, git push gating - still
apply on every mutation.)

## 7. Troubleshooting

- **"No marker found" and immediate exit (code 0).** Run QBAgent from the workspace root, or pass the
  workspace path as the first argument. The marker is created when McpServer starts.
- **Invalid marker (exit code 2).** The marker is missing `apiKey`/`baseUrl` or has a non-absolute
  `baseUrl`. Restart McpServer to regenerate the marker.
- **`401` from QuadBrain.** The workspace token rotated on a server restart; re-read the marker.
- **`git push` rejected.** Push is off by default and origin-only when enabled; push to `origin`, not a
  URL or a different remote.
- **`run_bash` reports unavailable.** Git Bash (`bash.exe`) is not on `PATH`; use `run_powershell`.
- **A file write is rejected.** The target is outside `Mcp:RepoAllowlist`; the server gates all writes.
